**Short answer: a clean `"1.5"` works, but `convert` isn't safe to feed raw form input.** It never checks the amount. JavaScript quietly turns the string into a number when it multiplies, so good input works by accident, and bad input returns a wrong number instead of an error.

:checked[convert does no type or validity check on amount]{src="src/convert.js:12-16"}. It only checks the two unit names, then returns `Math.round(amount * UNITS[from] / UNITS[to])`.

I ran it with form-style strings (cup → ml). Nothing threw:

| Input | Result | Problem |
|---|---|---|
| `"1.5"`, `" 1.5 "` | 355 | fine |
| `""` (empty field), `null` | 0 | blank field silently means 0 |
| `"1,5"` (comma decimal) | NaN | no error, NaN flows downstream |
| `"1/2"` (common in recipes) | NaN | same |
| `"abc"` | NaN | same |
| `"0x10"` | 3785 | read as hex 16 |
| `"1e3"` | 236588 | read as 1000 |
| `"Infinity"` | Infinity | accepted |

Two more things matter if the form input reaches this function:

- **Unit names from a form can get past the check.** :checked[the unit check uses `in`, which also matches built-in object properties]{src="src/convert.js:13-14"}, so `convert(1, "constructor", "ml")` returns NaN instead of throwing "unknown unit".
- **Small amounts round badly.** `convert("1.5", "tsp", "tbsp")` gives 1 (the true answer is 0.5), and ¼ tsp gives 1 ml. :checked[This rounding problem is already logged as I5]{src="docs/issues.md:9"}. It isn't about strings, but form users will hit it with spoon measures.

:guess[I'd fix this inside `convert` rather than in each form]: turn the amount into a number, throw unless it's a finite number ≥ 0, and check units with `Object.hasOwn`. :open-ask[Should blank, `"1/2"` and `"1,5"` throw, or should `convert` accept fractions and comma decimals?] That's a product decision.
