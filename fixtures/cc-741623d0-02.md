`convert` now accepts amounts typed as text, like `"1.5"`, and throws a clear error for anything that isn't a plain number. :checked[All 8 tests pass, including the 2 new ones]{src="node --test"}.

:changed[edited src/convert.js and test/convert.test.js]. Nothing was committed.

**What it accepts:**
- Real numbers, as before. NaN and Infinity now throw instead of producing a junk result.
- Text written as a plain decimal number: `"2"`, `"1.5"`, `".5"`, `"1."`. Spaces around it are fine, so `" 1.5 "` works.

**What it rejects:** everything else, including a blank field, `"1,5"`, `"1/2"`, `"0x10"`, `"1e3"`, `"Infinity"`, `null`, `undefined` and `true`. The error is a `TypeError` that shows the bad value and what was expected:

```
invalid amount: "1,5" (expected a number or a decimal string like "1.5")
```

**Tests added:** one checks that `"1.5"`, `" 2 "` and `".5"` convert correctly. The other runs each rejected value above and checks it throws `invalid amount`.

:open-default[Negative amounts like "-1.5" are still accepted]. I kept that so text input behaves the same as numbers (−1.5 was already allowed). A negative amount means nothing in a recipe, so I can reject both if you want.

**Not changed, from my earlier check:**
- Unit names like `"constructor"` still pass the unit check and return NaN instead of throwing "unknown unit".
- Small amounts still round to whole millilitres, so ¼ tsp gives 1 ml (issue I5).
- README.md line 32 still has the stray, out-of-date marker.
